### 画面质量与节奏

用户已接受 **1080p30 导出、平均约 29.4 fps 实际采集** 的实机试录；正式录制沿用该方案，使用源帧时间戳保持时序，逐段记录实际采集帧率。当前 WSL 软件渲染未达到原目标的实际 60 fps，不宣称已经达到。保持清晰等宽字体，中文 prompt 须另外验证可读且不裁切。只输出 MP4，不生成 GIF。旧片 VHS 的 Framerate 配置在阶段 1 为 15、阶段 3/4 为 10；成片标称 25 fps 不代表有相同数量的独立画面。

录制链路为真实 Shell/Qoder → ttyd → 无界面 Chromium → VHS 帧 → MP4。10/60 fps 对照均曾卡在页面初始化；增加 Chromium 的 `--disable-accelerated-2d-canvas --disable-gpu --disable-software-rasterizer` 后恢复；长片中文输入另加 `--headless=new`，仍须检查实际录制结果。tape 清空 MarginFill、将 Margin/BorderRadius 设为 0，避免默认装饰背景把成片限制为 25 fps。复用参数前先跑最小实录并检查实际画面，文件存在或退出码 0 不代表画面正确。具体实测、源帧和 MP4 见完整流程第 7.0.2 节。

保留输入、思考和输出的连续变化，避免每次工具调用都清屏换页。发送 prompt 前停留到足够读清；普通结果约 2～3 秒，首个关键拒绝及归因说明约 5～8 秒，按实际内容调整。等待真实完成使用条件检查，Sleep 只控制阅读节奏。若有剪辑/加速，必须显式标注并保留连续原片；不能用插帧或预制输出补造执行过程。

压缩讲解版的整片目标为 6～7 分钟：优先缩短命令输入、等待和重复展示，保留完整的解释、真实命令和关键结果。先写清对象、条件、动作与结果，再按旁白时长安排镜头；不能为了固定单段秒数省略授权条件或指代对象。已导出的讲解版总长 **6 分 55 秒**：第一段沿用已认可的 90 秒版本，阶段 2A 为 70 秒、2B 为 20 秒、阶段 3 为 90 秒、阶段 4 为 145 秒。普通话女声使用正常语速，字幕置于独立区域，避免遮挡终端。

历史原生 13 项证据保存在 AgentOS2 的 `/opt/asc-demo/asc-native-flow-253buz1r/`。本次 CLI 修订的独立证据目录为 `/opt/asc-demo/revision-check/`；位置查询已实测，连续性与录制工具须分别验收，不能把旧会话的 13 项结果作为当前版本的全部证明。

3. `policy get` 完整展示策略，随后用 `gateway key list` 查询真假凭据位置。阶段 1 展示导入源和 store，阶段 2A 原生导出后再次查询本 Scope 的假文件位置。位置属于 Gateway 运行时信息，不加到 Policy 响应中，也不得由录像控制器拼入字段。
4. 直接选择 `qodercli`、`ownerUid=1001`，在防护就绪后才发送首条任务。验证 Qoder 的工具后代继承防护；不把仅 READY 当成实际拦截证据。

## 3. 阶段 1：Host 创建策略并解释

开场说明：“Agent 要在本地处理一份合成客户数据，生成聚合报告并提交。我们先在 Host 部署三层防护，再观察同一个 Qoder 如何完成任务。”

### 3.1 Sandbox 基线

真实执行 `policy create`，使用返回的 ID/revision 执行 `policy get`；保留全部字段。

解释 Cedar 含义：“允许启动指定 Qoder 程序，允许读取运行依赖，仅允许工作目录写入，拒绝读取 `/root`。网络开启，使 Agent 可以请求模型和业务服务；请求的凭据和正文由 Host Gateway 继续检查。”

说明这份 Policy 是启动时 PDP 的授权基线，不加入后续文件/凭据 Scope。JSON 只封装 Cedar 的 schema 和源码，不把文件策略表述成 JSON 规则。

### 3.2 文件保护 Policy

真实 create/get，展示 Cedar 正文中 `keyfile`、`keyfile.alias` 及 write/delete 限制。

解释：“工作目录整体可写，但这两个指定路径额外受到 AgentSight 保护。硬链接两个名字都明确列入策略；不宣称自动保护任意新增别名。”

### 3.3 凭据 Policy 与真假凭据

展示合成测试真值的导入及权限，真实创建凭据 Policy，完整 get：元数据、effect/category/action、type/credentialId、scheme/host/path/methods、responseRewrite 均不省略。

旁白先解释具体条件：“这份网关策略先限定网址，也就是域名和接口路径，再为每个网址指定允许的 GET 或 POST 方法。”画面对应两项配置：`GET https://report.demo.test/v1/ping` 与 `POST https://report.demo.test/v1/reports`；网址和方法必须按这两组配对。随后解释动作：“只有网址和方法都匹配，网关才把请求里的假密钥替换成宿主机保存的真密钥。”以上是本 Demo 这份策略的授权范围。再解释 `buffered` 的响应缓冲和真值回写保护。

## 4. 阶段 2：Scope、Sandbox 与原生 Qoder

## 7. 证据、异常与交付

原生 Qoder 自行选择工具和命令，不要求固定 Bash 调用数量；curl 未使用 --fail 时，HTTP 403 与工具退出码 0 可以同时成立，须以实际 HTTP 响应和后台证据验收。

录制端可读取本轮原生会话的结束标记，并更新 tmux 的独立录制状态栏以结束该片段；该标记仅表示回合完成，不代表防护通过，不进入 Qoder 的产品输出。组件归因由实际事件核验；核验通过后，可在独立状态栏显示对应组件和实测结论，保留原生错误正文。

每次操作至少保留“完整 prompt → 真实工具调用 → 原始结果 → Qoder 反馈”；Host 在后台按实际工具时间和进程身份关联证据，不以历史同类事件或列表位置代替本次记录。

| 归因 | 后台必须核对 |
|---|---|
| Sandbox | 同 UID 宿主基线、目标 Qoder mount namespace 的只读限制、真实错误、文件未变；AgentSight 规则不覆盖该目标 |
| AgentSight | 对应 Binding/Policy、进程/后代、操作、目标及时间匹配的 blocked violation；目标路径/inode/摘要保留；同目录普通文件可写 |
| Gateway 凭据规则 | 实际 403/error/source、完整允许范围、目标请求未到上游 |
| PII | Gateway 本次请求对应扫描决策、输入 SHA-256/字节数、类型/数量、覆盖范围和上游零增量；排除 Qoder 遥测的额外扫描，不把模型端豁免当成 pass |
| 正常提交 | 实际 200、auth_ok、完整扫描 pass、上游收到相应报告；不能只看 Agent 总结 |

最终结果表由本次证据生成，不预填通过。Gateway 审计主体当前为 Gateway 发起的 CLI，通过时间和 flow 关联，不能称为原生全链路 Agent 身份追踪。

| 异常 | 处理 |
|---|---|
| Binding 或后端未就绪 | 不发送任务 prompt，保留诊断 |
| Qoder 仅口头拒绝、工具未执行 | 不计作 OS/Gateway 拦截，修正任务说明后重新验证 |
| 受保护修改意外成功或无归因证据 | 停止该 run，先修正文档/配置/实现，重跑相关步骤 |
